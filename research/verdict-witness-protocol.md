# Added-source verdict witness — invention and verification record

## System and reviewer problem

The Remembrance Field stores user-entered assertions in a local ledger and exports question, brief, and scoped excerpt receipts. A saved reference can be compared with a receipt in the page or by Node and independently written Python auditors. Batch and paired captures bind supplied file bytes, ordered receipts, outcomes, a browser script digest, and, in current captures, the selected-name normalization profile. A separate checkpoint can be kept before a later exchange. The strongest existing work is the replay path, refusal on malformed or ambiguous JSON, independently compared auditors, and explicit distinction between capture consistency and evidence truth.

This serves someone sharing a memory or claim and a reviewer asking whether a saved answer is consistent with a supplied ledger. The browser's local storage, selected files, and rules are separate trust boundaries; a capture, checkpoint, and verifier kit are still self-contained bytes unless preserved independently. A user may read `CAPTURE MATCH` as approval of every answer, mistake a repeated or omitted assertion for independent support, or interpret a hash as proof of origin.

Three consequential limits remain: **(1)** supplied assertions can be false or selectively omitted; **(2)** neither a hash nor a matching local capture establishes authorship, time, or independent custody; **(3)** deterministic rules can differ across runtimes, and bounded selected-name checks do not prove universal rule equivalence. An additional explanation gap was concrete: the existing minimum added-source **answer** witness could say `unchanged` while a full receipt changed from `MATCH` to `DIFFER` solely because its exact snapshot gained an unrelated record.

## Mechanism

For each successfully replayed receipt, compare its actual reference verdict under A and B. If unchanged, report that without claiming a witness. If the verdict differs, require B's ordered records restricted to A's source IDs to equal A's records exactly. This rejects edits, removals, and reorderings. With at most six added IDs, filter B to unchanged A records plus every chosen subset of additions, smallest sizes first. Replay the **receipt reference rule** on each hybrid. After testing every subset at the first successful size, show up to three tied minimum sets, the total tie count, and how many subsets were tested. At most 63 nonempty subsets are considered. The empty and full subsets correspond to A and B under this precondition. The output contains IDs and counts, not private names or values.

The verdict rule matters: a full question or brief receipt requires exact ordered records, whereas a scoped excerpt checks its answer and cited records and tolerates unrelated ledger records. A full snapshot can therefore have a one-source verdict witness and an **unchanged** answer. Conversely, an excerpt can remain `MATCH` under an unrelated addition. `FAIL` receipts receive no verdict counterfactual. Changed rules, missing files, or a mismatched saved capture stop paired replay before explanation. This is an exact minimum only in the declared bounded addition-only search space; it does not identify a real-world cause.

## Reproduce the before-and-after distinction

Use the synthetic baseline as A, [unrelated reference](example-verdict-witness-reference-unrelated.json) as B, and the existing excerpt and full receipt in that order. In the page, select B under **Compare with a saved reference**, select both receipts, then select A under **Trace a verdict across two references** and choose **Trace selected receipts**. The excerpt card remains `MATCH → MATCH`, with answer and verdict unchanged. The full card shows `MATCH → DIFFER`, answer unchanged, and verdict witness `#2` (one subset tested). Its amber witness panel explains exact snapshot scope without showing the fact's value. Optional A checkpoint may be selected; a checkpoint that differs stops the trace.

From the repository root, run both independently implemented auditors:

```bash
node tools/audit-evidence-batch.cjs research/example-evidence-reference-baseline.json research/example-evidence-excerpt.json research/example-evidence-receipt.json --checkpoint research/example-evidence-ledger-checkpoint.json --reference-b research/example-verdict-witness-reference-unrelated.json --check-transition research/example-verdict-witness-capture.json --explain-additions --explain-verdicts
python3 tools/independent-evidence-batch.py research/example-evidence-reference-baseline.json research/example-evidence-excerpt.json research/example-evidence-receipt.json --checkpoint research/example-evidence-ledger-checkpoint.json --reference-b research/example-verdict-witness-reference-unrelated.json --check-transition research/example-verdict-witness-capture.json --explain-additions --explain-verdicts
```

Both commands exit 0 after reproducing the capture. They report `A: 2 MATCH`, `B: 1 MATCH, 1 DIFFER`, unchanged computed answers, unchanged excerpt verdict, and full receipt minimum verdict set `#2`. Remove `--check-transition`: the ordinary paired audit exits 1 because B has a `DIFFER`. Add `--json` to receive `{transition, answer_influence, verdict_influence}`. Each explanation flag works independently; leaving both off preserves the original transition JSON. The witness sets are recomputed from originals and are **not** part of the capture. A saved legacy capture can still be replayed against its compatible archived code, but it cannot establish a missing browser profile.

The test suite also checks `DIFFER → MATCH` on a full receipt requiring two additions; tied alternatives for an excerpt; an unrelated excerpt staying matched; four tied sets with three displayed; edited, removed, reordered, and seven-source cases declining the search; malformed or forged receipts declining any witness; modified file bytes; missing or reordered receipt files; a tampered capture verdict or browser script digest; changed verifier/model digests; and a matching legacy transition whose originating normalization profile is absent. Node and Python agree on the synthetic results. A cross-runtime equality test on selected cases is evidence of implementation agreement there, not a proof of universal equivalence.

## Invention log and next move

**Problem:** a reviewer can confuse a changed computed answer with a changed receipt verdict. **Mechanism:** bounded minimum addition sets for the actual saved receipt comparison, shown beside the distinct answer witness, with the receipt's scope and abstention reasons. **Prior art to investigate:** delta debugging and minimal counterfactual explanations, plus provenance and evidence packaging systems used in archival review. The subset method and interface have not been searched for novelty; no patentability, commercial demand, or reviewer comprehension is established. **What remains unproven:** whether reviewers correctly interpret a `CAPTURE MATCH` with a `DIFFER` row, whether the separate panels reduce that error, and any factual or custody claim.

The next high-value integration is a small blinded reviewer study using matched captures containing `DIFFER` or `FAIL`, with preregistered comprehension questions about consistency, completeness, custody, and truth. A separately distributed and revocable verifier release channel may later improve code provenance, but it requires explicit publisher key custody and independently trusted distribution; a self-issued signature alone would not settle origin.
